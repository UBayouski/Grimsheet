# Implementation Plan: Skin and Sound

**Note: `skin-and-sound` builds on the finished `grid-ui`, `levels` and `error-monsters`, so `src/ui/` already holds `app.ts`, `render.ts`, `controller.ts`, `view-model.ts`, `key-map.ts`, `types.ts`, `strings.ts`, `error-look.ts` and `module.test.ts`, with `src/styles/grid-ui.css` and `src/styles/error-monsters.css`, and `src/main.ts` already imports the five real levels. It needs no other spec. The `hosting` tasks are independent of this plan: the only hosting file touched here is `scripts/check-dist.mjs` (task 2.2), and no other hosting task is started or changed.**

## Overview

The design uses TypeScript and CSS, so no implementation-language question is needed. The plan adds the skin and the sound on top of the finished UI in six batches, from the pure core outward to the browser, with the screenshots last:

1. Batch 1 (IDE, sequential) adds the shared types, strings and the pure sound module, then the controller and view model that produce `fx`, then the Key_Map row 13a (D21). The three tasks share `types.ts`, `strings.ts`, `controller.ts` and `key-map.ts`, so they run in order.
2. Batch 2 (Crew, parallel) adds the two disjoint deliverables that need only Batch 1: the Web Audio player, and the public assets with the hosting check change.
3. Batch 3 (IDE, sequential) rebuilds the DOM: `render.ts` with its tests, then `app.ts` wiring on top of it.
4. Batch 4 (IDE, sequential) writes the stylesheets with a visual check, then the entry points and the module scan.
5. Batch 5 (Crew, parallel) adds the new Playwright spec and edits the existing specs. The two tasks touch disjoint files.
6. Batch 6 (IDE, sequential) is the checkpoint, then the seven README screenshots, which are taken last.

Rules that apply to every task:

- Each task ends with the acceptance check `npm run verify` (`npm test`, then typecheck and lint). It stays green under `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax` and `noUnusedLocals`. The tasks that touch Playwright specs also need `npm run e2e` to pass. The screenshot task (6.2) runs the checks it lists plus `npm run verify`.
- Each task lists its Files and its Tests. There are no optional tasks, so no `*` markers are used. There are no property tests in this spec (Decision D15): example tables, fake-context tests and browser flows substitute for them.
- The layering holds: no file under `src/engine/`, `src/model/`, `src/game/` or `src/levels/` changes. `sound-events.ts` is pure and DOM-free (the Module_Scan scans it as `'pure'`: no `document`, `window`, `Event`, `AudioContext` or `globalThis`). `audio.ts` is the only file that names `AudioContext` and `globalThis`; it has no `document`, `window` or storage. `app.ts` stays the only place that touches `localStorage`, and reads `doc.defaultView`, never the identifier `window`.
- No `eval`, `new Function`, `Math.random`, `Date.now`, `new Date`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `style` attribute write, `window` identifier or AI tool name other than Kiro appears in any new or changed file under `src/`, in the stylesheets, in the HTML entries or in this spec folder. Test files under `src/ui/` are scanned for AI tool names too, so a test that must mention the CSS pointer-shape property (S13) builds the word from fragments, as `module.test.ts` does for its deny-list. No Product_Name ("Microsoft", "Windows", "Excel", "Lotus") appears anywhere outside the spec text.
- All player-visible strings live in `strings.ts`. Text reaches the DOM only through `textContent` and attribute setters.
- Pure UI tests run in the Node environment. `render.test.ts`, `app.test.ts` and any other DOM test start with the docblock `// @vitest-environment happy-dom`. `sound-events.test.ts`, `audio.test.ts`, `assets.test.ts` and `skin-css.test.ts` run in Node.
- Run mode: `[Crew]` tasks edit disjoint files and can run in parallel in Kiro Crew. `[IDE]` tasks share files or must run in sequence and run in the IDE.
- Single owners of shared files: `types.ts` (1.1, then 1.2) and `strings.ts` and `strings.test.ts` (1.1, with the padlock removal in 3.1), `controller.ts`, `view-model.ts` and their tests (1.2), `key-map.ts` and `key-map.test.ts` (1.3), `audio.ts` and `audio.test.ts` (2.1), `public/*`, `scripts/check-dist.mjs`, `README.md` and `assets.test.ts` (2.2), `render.ts` and `render.test.ts` (3.1), `app.ts` and `app.test.ts` (3.2), `src/styles/*` and `skin-css.test.ts` (4.1), `index.html`, `tests/fixtures/*`, `src/main.ts` and `module.test.ts` (4.2), `tests/e2e/skin.spec.ts` (5.1), the existing `tests/e2e/*.spec.ts` (5.2), `docs/screenshots/*` (6.2).
- No new dependency is added and `package.json` is not edited. The font ships as the unchanged TTF (D19): no woff2, no conversion tool.
