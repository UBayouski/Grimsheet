# Grimsheet — Product Brief

This is the input document for Kiro. Steering docs and specs are generated by Kiro from this brief, not written by
hand, so that `.kiro/` reflects real Kiro usage. Keep this file updated when scope changes.

## 1. One-liner

Grimsheet is a roguelike where the whole dungeon is a spreadsheet and you survive by editing formulas.

Tagline: **A roguelike where every monster is a formula.**
Hackathon: Kiroween 2026, category Frankenstein. Deadline Dec 4, 2026, 2:00 PM PT.

## 2. Who it is for and why it matters

- People who live in spreadsheets and have never seen one fight back.
- Puzzle and roguelike players who like games where the rules are visible and bendable.
- Anyone learning formulas: references, ranges, `IF`, dependency order and circular references are taught by playing,
  not by reading a manual.

The pitch for judges: a spreadsheet engine and a roguelike are two things nobody stitches together. Here the seam is
the game. Every rule (how a monster moves, how hard it hits, when a door opens) is an ordinary formula in a cell you
can read, and the player wins by rewriting those rules. Errors are not error messages; they are the monsters.

## 3. Core model

- **Sheet**: a fixed grid of cells. Columns `A` to `L`, rows `1` to `20`.
  - **Map area**: rows 1 to 12. Each cell's value is a terrain glyph.
  - **Rules panel**: rows 14 to 20. Named cells that hold the level's rules and stats, each with a text label in the
    cell to its left.
- **Cell**: address, optional formula, computed value, `locked` (read-only to the player), optional `name` (an
  upper-case identifier such as `HP`, `KEY`, `MOVE_M1`, unique per level).
- **Value**: number, string, boolean, or error (`#REF!`, `#NAME?`, `#DIV/0!`, `#VALUE!`, `#CYCLE!`).
- **Terrain glyphs**: `#` wall, `.` floor, `X` exit, `^` trap. Any other value, including any error, blocks movement.
- **Entities** sit on top of the map and are not cell values:
  - **Hero** `@`: position only. Formulas read it through the name `HERO`.
  - **Monster** `M`: id, position, a `move` rule and an `atk` rule, each the name of a rules-panel cell.
- **Level**: id, title, one-line hint, the cells (value or formula, locked, name), hero start, monsters, starting
  `HP`, an edit budget called **ink**, and an RNG seed. One JSON document per level; round-trip must be lossless.
- **Run state**: current level, sheet, entities, HP, ink left, turn number, one-step undo snapshot. Progress (levels
  cleared) persists in localStorage.

## 4. Formulas (frozen subset)

Freeze this list in the formula-engine spec. Anything not listed is out of scope for the hackathon.

**Syntax**
- A formula starts with `=`. A cell without `=` holds a literal: a number, or text taken as-is.
- Literals: numbers (`3`, `2.5`), strings in double quotes (`"#"`), `TRUE`, `FALSE`.
- Operators, by precedence: unary `-`; `*` `/`; `+` `-`; `&` (text join); `=` `<>` `<` `>` `<=` `>=`.
  Parentheses group.
- References: a cell (`B9`), a range (`A14:A20`) inside a function argument only, or a cell name (`HP`, `KEY`).
- Special names: `HERO` (the hero's cell) and `SELF` (the monster whose rule is being evaluated; `#REF!` elsewhere).

**Functions**
- `SUM(range or values...)`, `MIN(...)`, `MAX(...)`, `ABS(x)`, `MOD(a, b)`.
- `IF(cond, then, else)`, `AND(...)`, `OR(...)`, `NOT(x)`.
- `ROW(ref)`, `COL(ref)`: 1-based row and column of a reference.
- `DIST(a, b)`: Manhattan distance between two references.
- `TOWARD(target)`: one of `"N"`, `"S"`, `"E"`, `"W"`, the step from `SELF` toward `target` along the axis with the
  larger distance (ties go vertical), or `"-"` when already there.
- `RAND()`: a number in [0, 1) from the level's seeded generator. Same seed, same game.

**Evaluation rules**
- Recalculation follows the dependency graph in topological order. The result never depends on the order cells were
  defined or edited.
- Evaluation never throws. Every cell ends as a value or an error.
- Errors: a reference outside the sheet or to an unknown name is `#REF!`; an unknown function is `#NAME?`; division
  by zero is `#DIV/0!`; a wrong type (text where a number is needed) is `#VALUE!`; every cell on a circular reference
  is `#CYCLE!`. An error in an argument propagates, except inside the branch `IF` does not take.
- Parse errors are reported as `Col N: <message>.` in the formula bar and the edit is refused (no ink spent).

**Not included**: absolute references (`$A$1`), other sheets, dates, text functions other than `&`, array formulas,
`INDIRECT`, user-defined functions, iterative calculation.

## 5. Game rules

**A turn**
1. The player acts: move one cell with the arrow keys, wait with Space, or commit a formula edit (costs 1 ink).
2. A move succeeds only if the target cell's value is walkable (`.`, `X`, `^`) and no monster is there.
3. The sheet recalculates.
4. Each monster, in reading order, evaluates its `move` rule with `SELF` bound to it. A result of `"N"`, `"S"`,
   `"E"` or `"W"` moves it one cell if that cell is floor and empty; anything else, including an error, leaves it in
   place. Then its `atk` rule is evaluated and a positive number is subtracted from `HP`.
5. A hero standing on `^` loses the value of the `TRAP` cell.
6. While any `#CYCLE!` exists, the sheet is haunted and the hero loses 1 HP.
7. The sheet recalculates. The hero on `X` wins the level. `HP` at 0 or below loses it.

**Editing**
- Clicking a cell shows its formula in the formula bar. Locked cells show a padlock and cannot be edited.
- Committing a changed formula on an unlocked cell spends 1 ink. No ink, no edits.
- One-step undo reverts the last turn or edit, refunding ink.

**The point of the game**: breaking a monster's rule is a legal strategy. A monster whose `move` rule errors stands
still; a monster whose `atk` rule errors cannot hurt you. A wall cell whose formula you fix can become floor. The
puzzle is choosing which formula to change with the ink you have.

## 6. Errors are monsters

Each error has a look and a game effect, so the spooky layer does a job:

| Error | Look | Effect |
|---|---|---|
| `#REF!` | A coffin: a dead reference | Blocks movement on the map |
| `#NAME?` | A tombstone with a blank name | Blocks movement on the map |
| `#DIV/0!` | A crack into the void | Blocks movement on the map |
| `#VALUE!` | A wilted, grey cell | Blocks movement on the map |
| `#CYCLE!` | A ghost drifting along the cycle | Haunts: 1 HP per turn until the cycle is broken |

Hovering an error cell names its cause in plain English, such as "B9 refers to M30, which does not exist".

## 6a. Story and names

- Premise: you opened GRIMSHEET.XLS, a workbook found on a dead accountant's floppy disk. Its formulas are alive.
  The workbook's hidden rules sheet is the **Necronomicell**: the book of formulas that animates every monster.
- The rules panel (rows 14 to 20) is titled "NECRONOMICELL". Editing it is reading from the forbidden book.
- Each level is a sheet tab: "Sheet1: The Corridor" through "Sheet5: The Lich".
- Death screen: the dialog title is "#REF! of the Dead", the body reads "GRIMSHEET.XLS has stopped responding",
  and the button is Recover.
- Win screen: "Workbook saved. Your soul was not." on the last level; "Changes saved." on the others.
- Flavor text is short and dry, in the voice of a cursed office tool: status-bar tips, tooltips and error
  causes. No long cutscenes. All text lives in one strings file so tone can be tuned in one place.

## 7. Levels

Five hand-written levels as JSON, each teaching one idea:

1. **The Corridor**: move, reach the exit, read a formula. No monsters.
2. **The Chaser**: a monster with `=IF(DIST(HERO,SELF)<4, TOWARD(HERO), "-")`. Change its range to survive.
3. **The Locked Crypt**: the door is `=IF(KEY=1337,".","#")`. Work out which cells feed `KEY`.
4. **The Trap Row**: a row of `^` and a `#DIV/0!` tombstone blocking the safe path. Fix the formula behind it.
5. **The Lich**: a boss whose `HP` formula can never reach 0 and a circular reference haunting the room.

Every level must be winnable within its ink and HP. This is checked by an automated solver test, not by hand.

## 8. Visual design

- A spreadsheet that has gone wrong. Late-1990s office chrome: grey bevels, column letters, row numbers, gridlines,
  a formula bar, a status bar with HP, ink and turn. Title bar reads `GRIMSHEET.XLS`. No real product names,
  logos or trademarks anywhere.
- Cells are square and monospace. Glyphs first; optional 16×16 sprites for hero, monster and the error monsters.
- Small animations only: recalculated cells flash, the hero slides one cell, the ghost drifts, the sheet shakes on
  damage. Respect `prefers-reduced-motion`.
- Title screen as a spreadsheet splash. The death screen is a dialog: "GRIMSHEET.XLS has stopped responding" with a
  Recover button that restarts the level.
- Sound: a few short square-wave beeps from Web Audio, generated in code. No sound files.
- Open-licensed fonts only, self-hosted.

## 9. Technical choices

- TypeScript (strict), Vite, no UI framework. The grid is a DOM table; CSS for the chrome.
- Formula engine: hand-written tokenizer, recursive-descent parser to an AST, evaluator over a dependency graph.
  No `eval`, no `new Function`. DOM-free so it runs in tests and in a headless solver.
- Tests: Vitest for unit tests, fast-check for property-based tests, Playwright for end-to-end.
- Hosting: a static site, no backend, no API keys, no AI calls at run time. Free and always on until Jan 29, 2027.
- Node 22+. `npm run dev`, `npm test`, `npm run build`, `npm run e2e`.
- Written from scratch. No code is shared with any other project.

## 10. Non-goals

- Spreadsheet compatibility, importing `.xlsx` or `.csv` files.
- A level editor, user-made levels, multiplayer, accounts, leaderboards.
- Procedural level generation.
- Mobile play (it should render on a phone, but the game is for keyboard and mouse).

2. `sheet-model`: cell and level types, level JSON schema, loader, lossless round-trip.
